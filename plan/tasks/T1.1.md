# T1.1 — BE: đăng ký tài khoản, xác thực email, quên mật khẩu

- **Nhóm:** G1
- **Nhánh:** `task/T1.1-register` (tạo từ `main`)
- **UC liên quan:** UC01 (đăng ký, xác thực email, gửi lại email) · UC02 luồng con quên mật khẩu
- **Phụ thuộc:** D7, D1, T0.2, T0.4, T0.5 (done)
- **Tham chiếu:** `docs/specs/g1-account.md` (BR01–BR15, API, mã lỗi, mục 7 consumer),
  PROJECT.md mục 8 (quy tắc tài khoản), `docs/design/base-reference.md`, AGENTS.md

## 1. Mục tiêu

Sau task này người dùng **đăng ký được tài khoản** (Người tham dự / Ban tổ chức / Nhà cung cấp),
**nhận email xác thực** thật (xem trong smtp4dev), bấm link để **xác thực**, **gửi lại** email, và
**đặt lại mật khẩu** khi quên. Chưa đăng nhập được (T1.4). Thử toàn bộ qua Scalar.

Đây cũng là task đầu tiên có **bảng nghiệp vụ** và **sự kiện nghiệp vụ**, nên dựng luôn các cơ chế
nền mà mọi nhóm sau dùng lại:
- Repository + Specification cho aggregate.
- Tự ghi `CreatedAt` (audit) và Guid tuần tự khi thêm bản ghi.
- **Domain event → message → outbox**: aggregate chỉ "ghi lại việc đã xảy ra"; repository đổi thành
  message và publish qua outbox ngay trước `SaveChanges` → dữ liệu và message cùng một transaction.
- Consumer đầu tiên (gửi email) + MailKit + smtp4dev.

## 2. Phạm vi

**Làm:**
- Domain: `Role`, `User`, `UserToken` + enum trạng thái / mục đích + 3 domain event.

- 5 endpoint: `register`, `verify-email`, `resend-verification`, `forgot-password`, `reset-password`.
- 2 consumer gửi email (xác thực, đặt lại mật khẩu) theo 5 bước ở `g1-account.md` mục 7.
- Rate limit cho 5 endpoint trên (BR15), số lần cấu hình được (Options pattern).
- `docker-compose.yml`: thêm `smtp4dev`.
- Kiểm tra còn nợ từ T0.4: tắt RabbitMQ thì `/health` báo `Unhealthy` (mục 7).

**Không làm (để task khác):**
- Đăng nhập, JWT, refresh token, đăng xuất, `/me`, phân quyền `[MustHavePermission]`,
  danh mục quyền, seed tài khoản mẫu → **T1.4**. (Reset mật khẩu vẫn thu hồi token `Refresh` còn hạn —
  bảng đã có sẵn Purpose này; T1.4 mới bắt đầu sinh ra chúng.)
- CORS cho frontend, giao diện → T1.2, T1.3.
- Hồ sơ, đổi mật khẩu khi đang đăng nhập (UC41), QT duyệt/khóa (UC20).
- Lưu ngôn ngữ của người dùng (email gồm cả vi + en).

## 3. Thiết kế

### Luồng tổng

```
Đăng ký:   AuthController → RegisterCommand → ValidationBehavior → RegisterCommandHandler
             → User.Register(...)          (aggregate ghi domain event UserRegistered)
             → IRepository<User>.AddAsync  (EfRepository.SaveChangesAsync:
                  1. đổi domain event → SendVerificationEmailMessage, Publish vào outbox
                  2. DbContext.SaveChanges: AuditInterceptor gán CreatedAt
                     → User + OutboxMessage ghi CÙNG transaction)
           → outbox nền → RabbitMQ → SendVerificationEmailConsumer
             → SendVerificationEmailCommand → handler: 5 bước (g1-account.md mục 7) → IEmailSender (MailKit)
Xác thực:  AuthController → VerifyEmailCommand → handler: tìm token theo SHA-256
             → token.MarkUsed + user.VerifyEmail() → SaveChanges một lần (cùng transaction)
```

### CSDL (migration `T1_1_Accounts`)

Mọi entity kế thừa `BaseEntity`: thêm `CreatedAt` (`DateTime`, UTC, `datetime2`) — gán bởi
`AuditInterceptor`, không gán tay. Enum lưu chuỗi (`HasConversion<string>()`, tối đa 30 ký tự).

| Bảng       | Ràng buộc / chỉ mục                                   |
|------------|-------------------------------------------------------|
| Roles      | UQ `Code`; seed 5 dòng                                |
| Users      | UQ `Email`; FK `RoleId` → Roles                       |
| UserTokens | UQ `TokenHash`; IX (`UserId`, `Purpose`); FK `UserId` |

Cột (độ dài chuỗi trong ngoặc):
- **Roles:** `Code` (30), `Name` (100), `Permissions` (JSON).
- **Users:** `Email` (256), `PasswordHash` (256), `FullName` (100), `RoleId`, `Organization` (200, null),
  `Bio` (1000, null — chưa dùng, để UC41), `Status` (30).
- **UserTokens:** `UserId`, `Purpose` (30), `TokenHash` (64), `ExpiresAt`, `UsedAt` (null).

- `Role.Permissions` là `List<string>` → EF Core tự lưu thành cột JSON (primitive collection).
  Seed bằng `HasData` với Id cố định; nếu EF không seed được primitive collection thì báo Claude.
- 5 vai trò seed: `Attendee` Người tham dự · `Organizer` Ban tổ chức · `Supplier` Nhà cung cấp ·
  `Staff` Nhân viên vận hành · `Admin` Quản trị viên.
- Không có bảng Outbox mới (T0.4 đã có).
- **Guid tuần tự:** dùng sẵn `SequentialGuidValueGenerator` của EF Core SQL Server (khóa Guid mặc định
  `ValueGeneratedOnAdd`) — Id có ngay khi `Add`, trước `SaveChanges`. Không tự viết bộ sinh Id.
  Test phải chứng minh Id khác `Guid.Empty` sau `Add`.

### Domain (`ConfHub.Domain/Accounts/`)

- **`RoleCodes`** — hằng số 5 mã vai trò.
- **`Role`** (aggregate root) — `Code`, `Name`, `Permissions`; `CanSelfRegister` (Attendee, Organizer,
  Supplier), `RequiresApproval` (Organizer, Supplier). Constructor private; tạo qua
  `Role.Create(id, code, name)` (dùng cho seed và test).
- **`UserStatus`**: `Unverified`, `PendingApproval`, `Active`, `Locked`.
- **`User`** (aggregate root), không public setter:
  - `static Register(email, passwordHash, fullName, Role role, organization)` — cắt khoảng trắng +
    chữ thường email; `role.CanSelfRegister` sai → `DomainException("RoleNotAllowed")`;
    `role.RequiresApproval` mà thiếu organization → `DomainException("OrganizationRequired")`;
    trạng thái `Unverified`; ghi `UserRegistered`.
  - `RequestVerificationEmail()` — chỉ khi `Unverified`; ghi `VerificationEmailRequested`.
  - `VerifyEmail()` — chỉ khi `Unverified` → `Active` hoặc `PendingApproval` theo `Role.RequiresApproval`
    (cần `Role` đã được nạp). Sai trạng thái → `DomainException("AlreadyVerified")`.
  - `RequestPasswordReset()` — chỉ khi `Active` / `PendingApproval`; ghi `PasswordResetRequested`.
  - `ResetPassword(newPasswordHash)` — chỉ khi `Active` / `PendingApproval`.
  - Mọi lỗi trạng thái dùng `DomainException` với mã rõ nghĩa.
- **`TokenPurpose`**: `VerifyEmail`, `ResetPassword`, `Refresh`.
- **`UserToken`** (aggregate root riêng — vòng đời độc lập, tra theo hash):
  `static Issue(userId, purpose, tokenHash, expiresAt)`, `IsActive(DateTime now)`
  (`UsedAt == null && ExpiresAt > now`), `MarkUsed(DateTime now)` (đã dùng → `DomainException`).
- **Events/**: `UserRegistered(User User)`, `VerificationEmailRequested(User User)`,
  `PasswordResetRequested(User User)`. Mang **tham chiếu tới User** (không phải `Guid`) vì lúc aggregate
  ghi event thì Id chưa có; lúc publish (trước `SaveChanges`) Id đã được EF gán.
- Domain nhận thời gian qua tham số `DateTime now`, không gọi `DateTime.UtcNow`.

### Application (`ConfHub.Application/`)

- **Common/Persistence**: `IRepository<T>` (: `IRepositoryBase<T>`), `IReadRepository<T>`
  (: `IReadRepositoryBase<T>`), ràng buộc `T : class, IAggregateRoot`.
- **Common/Security**: `SecureToken` (static) — `Generate()` 32 byte ngẫu nhiên
  (`RandomNumberGenerator`) → Base64Url; `Hash(raw)` → SHA-256 → chuỗi hex 64 ký tự.
  `IPasswordHasher` — `Hash(password)`, `Verify(hash, password)`.
- **Common/Email**: `IEmailSender` — `SendVerificationEmailAsync(email, fullName, token, ct)`,
  `SendPasswordResetEmailAsync(email, fullName, token, ct)`.
- **Accounts/**:
  - `AccountErrorCodes` — `EmailTaken`, `TokenInvalid` (+ mã validator tự đặt).
  - `TokenLifetimes` — VerifyEmail 24 giờ, ResetPassword 30 phút, ResendCooldown 60 giây.
  - `PasswordRules` — extension FluentValidation dùng chung cho đăng ký và đặt lại mật khẩu (BR02).
  - `Messages/`: `SendVerificationEmailMessage(Guid UserId)`, `SendPasswordResetEmailMessage(Guid UserId)`.
  - `Specifications/`: `UserByEmailSpec` (kèm Role), `UserByIdSpec` (kèm Role), `RoleByCodeSpec`,
    `TokenByHashSpec`, `ActiveTokensSpec(userId, purpose, now)`, `LatestTokenSpec(userId, purpose)`.
  - Mỗi use case 1 thư mục (Command + Validator + Handler, + Response nếu có):

| Thư mục                   | Gọi từ                                   |
|---------------------------|------------------------------------------|
| `Register`                | `POST /register`                         |
| `VerifyEmail`             | `POST /verify-email`                     |
| `ResendVerificationEmail` | `POST /resend-verification`              |
| `ForgotPassword`          | `POST /forgot-password`                  |
| `ResetPassword`           | `POST /reset-password`                   |
| `SendVerificationEmail`   | Consumer `SendVerificationEmailMessage`  |
| `SendPasswordResetEmail`  | Consumer `SendPasswordResetEmailMessage` |

Handler làm gì:
- **Register:** email (đã chuẩn hóa) đã có → `ConflictException(EmailTaken)`; tìm Role theo mã; băm
  mật khẩu; `User.Register`; `AddAsync`. Trả `{ email }`.
- **VerifyEmail:** hash token → tìm; không có / sai Purpose / `!IsActive(now)` → `TokenInvalid`; nạp
  User (kèm Role); User khác `Unverified` → `TokenInvalid`; `token.MarkUsed` + `user.VerifyEmail`;
  lưu 1 lần. Trả `{ status }`.
- **ResendVerificationEmail:** User tồn tại và `Unverified` → `RequestVerificationEmail` + lưu;
  khác → không làm gì.
- **ForgotPassword:** `Unverified` → `RequestVerificationEmail`; `Active` / `PendingApproval` →
  `RequestPasswordReset`; còn lại hoặc không tồn tại → không làm gì. Luôn trả như nhau.
- **ResetPassword:** kiểm token như VerifyEmail (Purpose `ResetPassword`); băm mật khẩu mới;
  `user.ResetPassword`; `MarkUsed`; thu hồi mọi token `Refresh` còn hạn của user; lưu 1 lần.
- **SendVerificationEmail / SendPasswordResetEmail:** 5 bước consumer ở `g1-account.md` mục 7
  (kiểm trạng thái → cooldown 60 giây → thu hồi token cũ → tạo token → gửi mail).

- `TokenInvalid` ném `DomainException(AccountErrorCodes.TokenInvalid, ...)` → middleware T0.5 trả 422.
  Mọi trường hợp token sai (không có, hết hạn, đã dùng, sai mục đích) dùng **cùng một mã và thông điệp**.
- "Lưu 1 lần": sửa các entity đang được theo dõi rồi gọi `SaveChangesAsync()` của repository một lần —
  cùng `DbContext` nên mọi thay đổi vào chung một transaction.
- Validator (mã lỗi dùng cho FE dịch):
  - `RegisterCommand`: FullName 2–100 sau trim; Email đúng định dạng, ≤ 256; Password theo `PasswordRules`
    (8–128, có chữ cái và chữ số — mã `PasswordNeedsLetterAndDigit`); Role thuộc 3 vai trò tự đăng ký
    (mã `RoleNotAllowed`); Organization ≤ 200, bắt buộc với Organizer/Supplier (mã `OrganizationRequired`).
  - `VerifyEmailCommand`, `ResetPasswordCommand`: Token không rỗng, ≤ 100; NewPassword theo `PasswordRules`.
  - `ResendVerificationEmailCommand`, `ForgotPasswordCommand`: Email không rỗng, đúng định dạng.

### Infrastructure (`ConfHub.Infrastructure/`)

- **Persistence/Configurations/**: `RoleConfiguration` (+ seed), `UserConfiguration`, `UserTokenConfiguration`.
- **Persistence/AuditInterceptor** (`SaveChangesInterceptor`): entity `Added` kế thừa `BaseEntity` →
  gán `CreatedAt = timeProvider.GetUtcNow().UtcDateTime`.
- **Persistence/DomainEventPublisher**: lấy mọi entity đang được theo dõi có domain event, đổi từng event
  thành message (`if`/`switch` rõ ràng: `UserRegistered`, `VerificationEmailRequested` →
  `SendVerificationEmailMessage`; `PasswordResetRequested` → `SendPasswordResetEmailMessage`),
  `IPublishEndpoint.Publish`, rồi `ClearDomainEvents()`. Event chưa có ánh xạ → ném exception (không bỏ qua im lặng).
- **Persistence/EfRepository<T>** (: `RepositoryBase<T>`): override `SaveChangesAsync` →
  `DomainEventPublisher` trước, rồi `base.SaveChangesAsync`; bắt `DbUpdateException` do trùng unique
  (SQL 2601/2627) → `ConflictException("Duplicate")` (hai người đăng ký cùng email cùng lúc).
  - **Vì sao publish ở repository, không ở interceptor:** interceptor cần `IPublishEndpoint`, mà
    `IPublishEndpoint` (outbox) lại cần `DbContext` → vòng phụ thuộc khi tạo `DbContext`.
  - Quy ước từ nay: **ghi dữ liệu nghiệp vụ luôn qua repository** để domain event không bị bỏ sót.
  - Codex kiểm tra `AddAsync` / `UpdateAsync` của Ardalis có gọi `SaveChangesAsync` (virtual) — nếu không, báo Claude.
- **Security/AspNetPasswordHasher**: bọc `PasswordHasher<object>` của ASP.NET Core Identity (PBKDF2);
  `Verify` coi `SuccessRehashNeeded` là đúng.
- **Email/**: `SmtpOptions`, `FrontendOptions` (Options pattern), `SmtpEmailSender` (MailKit): dựng link
  `{Frontend.BaseUrl}/verify-email?token=...` (hoặc `/reset-password`), token qua `Uri.EscapeDataString`,
  tên người dùng qua `WebUtility.HtmlEncode`; thân mail HTML có cả vi và en, ghi hạn của link.
  Không ghi token vào log.
- **Messaging/Consumers/**: `SendVerificationEmailConsumer`, `SendPasswordResetEmailConsumer` — chỉ gọi
  `ISender.Send(new ...Command(message.UserId))`; logic nằm ở handler Application.
- **DependencyInjection**: đăng ký các mục ở phần "Hạ tầng mới"; `AddDbContext` thêm `AuditInterceptor`.

### Api (`ConfHub.Api/`)

- **Controllers/AuthController** (`[ApiController]`, `[Route("api/auth")]`, `[AllowAnonymous]`), gọi `ISender`:

| Method | Route                  | Rate limit policy | Thành công       |
|--------|------------------------|-------------------|------------------|
| POST   | `/register`            | `Register`        | 201 `{ email }`  |
| POST   | `/verify-email`        | –                 | 200 `{ status }` |
| POST   | `/resend-verification` | `Email`           | 202 (luôn luôn)  |
| POST   | `/forgot-password`     | `Email`           | 202 (luôn luôn)  |
| POST   | `/reset-password`      | `ResetPassword`   | 204              |

- **RateLimiting/**: `AuthRateLimitOptions`, `RateLimitPolicies` (tên policy), extension
  `AddAuthRateLimiting`: fixed window 1 phút, phân vùng theo IP (`RemoteIpAddress`, null → `"unknown"`);
  bị chặn → 429 ProblemDetails `code = TooManyRequests` (cùng định dạng middleware).
- **Program.cs**: `AddAuthRateLimiting(configuration)`; `app.UseRateLimiter()` đặt trước `MapControllers`.

### Quy tắc bảo mật phải giữ

- Chỉ lưu bản băm mật khẩu (PBKDF2) và token (SHA-256). Token gốc chỉ có trong email.
- Không log mật khẩu, token, thân email. Message chỉ mang `UserId`.
- `resend-verification`, `forgot-password` trả **giống hệt nhau** dù email có hay không (BR09).
- Validate lại mọi thứ ở backend, kể cả `Role` (không tin giao diện).
