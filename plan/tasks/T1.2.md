## 1. Mục tiêu

Sau task này người dùng làm được toàn bộ UC01, UC02 **trên giao diện**: đăng ký → nhận email (xem trong
smtp4dev) → bấm link xác thực → đăng nhập → header hiện tên + menu → đăng xuất; quên mật khẩu → nhận
email → đặt mật khẩu mới. Tải lại trang vẫn còn đăng nhập (làm mới phiên bằng cookie). **G1 xong.**

Đây cũng là task FE đầu tiên gọi API, nên dựng luôn phần nền mà mọi nhóm sau dùng lại:
- `lib/apiClient.ts`: một chỗ gọi backend — gắn access token, đổi lỗi ProblemDetails thành `ApiError`,
  hết hạn access token thì tự làm mới **một lần** rồi gửi lại.
- `lib/authSession.ts`: giữ access token + người dùng **trong bộ nhớ** (không `localStorage`).
- TanStack Query cho mọi lần gọi API; chữ lỗi dịch theo `code` backend trả về.

## 3. Thiết kế

### Luồng tổng

```
Trang (page) → component (form) → hook (useMutation của TanStack Query) → api.ts (1 hàm / 1 endpoint)
  → lib/apiClient.ts  axios "/api/..." (interceptor gắn Bearer) ──► Vite proxy ──► backend :5065
      lỗi → ApiError { status, code, fieldErrors } → form hiện lỗi theo ô / Alert theo code

Mở trang: SessionBootstrap → refreshSession() → có cookie hợp lệ → authSession = { accessToken, user }
Gọi API cần đăng nhập mà 401: apiClient → refreshSession() (dùng chung 1 lần gọi) → gửi lại request
  → làm mới thất bại → clearSession() → về /login?reason=sessionExpired
```

### Hạ tầng mới

- Gói: `@tanstack/react-query` (v5), `axios` (gọi API — Huy chốt 2026-10-09, ghi cố định bản `1.20.0`);
  dev: `axios-mock-adapter` (test giả response của axios, không cần backend). Không thư viện form ngoài
  `Form` của antd, không msw.
- `vite.config.ts`: `server.proxy` `"/api"` → `http://localhost:5065` (cổng HTTP trong
  `launchSettings.json` của API). Cùng địa chỉ nên cookie `confhub_refresh` (`SameSite=Strict`,
  `Path=/api/auth`) gửi đi bình thường, không cần CORS.
- `AppProviders`: thêm `QueryClientProvider` (mutation `retry: false`; query `retry: false`,
  `refetchOnWindowFocus: false`) và `SessionBootstrap`; thêm `App` của antd (để dùng `message`).

### lib — dùng chung mọi nhóm

| File                 | Nội dung                                                                                                                       |
|----------------------|--------------------------------------------------------------------------------------------------------------------------------|
| `lib/apiError.ts`    | `class ApiError extends Error { status; code; fieldErrors: Record<string, string[]> }` + `isApiError()`                        |
| `lib/authSession.ts` | Kho phiên trong bộ nhớ: `getAccessToken`, `getSession`, `setSession`, `clearSession`, `subscribe` (cho `useSyncExternalStore`) |
| `lib/apiClient.ts`   | `apiClient` (đối tượng axios, `baseURL: "/api"`, 2 interceptor) + `refreshSession()`                                          |

`apiClient`:
- `axios.create({ baseURL: "/api" })`; cùng địa chỉ nên trình duyệt tự gửi cookie. Interceptor request:
  có access token thì thêm `Authorization: Bearer …`. Hàm trong `api.ts` gọi `apiClient.post<T>(...)` rồi
  trả `response.data` (202 / 204 không cần dữ liệu).
- Interceptor response, lỗi: đọc ProblemDetails → `ApiError` (`code` từ trường `code`; `fieldErrors` từ
  `errors`, tên trường đổi chữ đầu thành thường: `Email` → `email`). Không có response (mất mạng) →
  `status = 0, code = "Network"`; body không phải JSON → `code = "Network"`.
- 401 khi **đang có** access token và request không phải của `api/auth/*` → `refreshSession()` một lần
  rồi gửi lại; vẫn 401 hoặc làm mới thất bại → `clearSession()`, chuyển `/login?reason=sessionExpired`.
- **`refreshSession()` chỉ có tối đa 1 request đang bay:** lần gọi thứ hai trong lúc lần đầu chưa xong
  nhận lại cùng `Promise`. Bắt buộc, vì refresh token xoay vòng: hai request cùng gửi một cookie thì
  backend coi là token bị đánh cắp và thu hồi mọi phiên (BR12). (StrictMode của React chạy effect 2 lần
  ở máy dev — đúng tình huống này.)

### features/auth — nhóm chức năng Tài khoản

- `types.ts`: `RegisterRequest`, `RegisterResponse`, `VerifyEmailResponse` (status), `LoginRequest`,
  `ResetPasswordRequest`. (`RoleCode`, `CurrentUser`, `SessionResponse` nằm ở `lib/authSession.ts` vì
  `lib` không được phụ thuộc `features`.)
- `api.ts`: 7 hàm — `register`, `verifyEmail`, `resendVerification`, `forgotPassword`, `resetPassword`,
  `login`, `logout` (gọi `/auth/refresh` nằm trong `lib/apiClient`).
- `roleLandingPaths.ts`: bảng vai trò → trang đầu (hiện mọi vai trò `/`) + hàm
  `resolvePostLoginPath(user, returnUrl)`: `returnUrl` chỉ nhận đường dẫn nội bộ (bắt đầu bằng `/`,
  không bắt đầu bằng `//`) — chống chuyển hướng sang trang ngoài.
- `hooks/`: `useAuthSession` (đọc kho phiên qua `useSyncExternalStore`), `useLogin`, `useLogout`,
  `useRegister`, `useVerifyEmail`, `useResendVerification`, `useForgotPassword`, `useResetPassword`.
- `components/`: `AuthCard` (thẻ giữa trang: tiêu đề + mô tả + nội dung), `RegisterForm`, `LoginForm`,
  `ForgotPasswordForm`, `ResetPasswordForm`, `ResendVerificationForm` (ô email + nút, dùng ở trang xác
  thực khi link hỏng), `ResendCountdownButton` (nút gửi lại khóa 60 giây, đếm ngược — BR08),
  `GuestHeaderActions` (Đăng nhập / Đăng ký), `UserMenu` (tên + `Dropdown`: email, vai trò, Đăng xuất),
  `SessionBootstrap` (gọi `refreshSession` 1 lần khi mở app, hiện `Spin` toàn trang tới khi xong).
- `pages/`: 6 trang ở bảng dưới.

### Màn hình (theo `docs/ui/g1-account.html`)

| Route                       | Trang                | Hành vi chính                                                                                                                                                                               |
|-----------------------------|----------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `/register`                 | `RegisterPage`       | Chọn vai trò (`Radio.Group` 3 thẻ); BTC / NCC hiện ô Đơn vị (bắt buộc) + ghi chú cần duyệt; xong → `/register/check-email?email=…`                                                          |
| `/register/check-email`     | `CheckEmailPage`     | Hiện email; nút gửi lại khóa 60 giây ngay khi vào trang; gửi xong hiện thông báo chung (BR09)                                                                                               |
| `/verify-email?token=`      | `VerifyEmailPage`    | Gửi token 1 lần → `Active`: thành công + nút Đăng nhập · `PendingApproval`: chờ duyệt · `TokenInvalid` / thiếu token: hỏng + `ResendVerificationForm`                                       |
| `/login?returnUrl=&reason=` | `LoginPage`          | Lỗi theo `code` (`InvalidCredentials`, `AccountUnverified` + link gửi lại, `AccountPending`, `AccountLocked`); `reason=sessionExpired` → Alert phiên hết hạn; xong → `resolvePostLoginPath` |
| `/forgot-password`          | `ForgotPasswordPage` | Gửi xong luôn hiện cùng một thông báo (BR09) + link về đăng nhập                                                                                                                            |
| `/reset-password?token=`    | `ResetPasswordPage`  | Mật khẩu mới + nhập lại → thành công + nút Đăng nhập · `TokenInvalid` → hỏng + link quên mật khẩu                                                                                           |

- `/register`, `/login`, `/forgot-password` khi **đã đăng nhập** → chuyển về `/`.
- `VerifyEmailPage` dùng `useQuery` (khóa = token, `retry: false`, `staleTime: Infinity`) thay vì
  `useMutation` trong effect: StrictMode vẽ trang 2 lần mà vẫn chỉ 1 request (lần 2 sẽ bị 422 vì token
  đã dùng).
- Đăng xuất: gọi `logout` → `clearSession()` → `queryClient.clear()` → về `/`. Gọi API lỗi vẫn xóa
  phiên ở giao diện.

### Kiểm tra dữ liệu trên form (trùng quy tắc backend, BR01–BR04)

- Họ tên 2–100 ký tự (sau khi cắt khoảng trắng) · email đúng định dạng, ≤ 256 · mật khẩu 8–128, có chữ
  cái và chữ số · nhập lại khớp · đơn vị bắt buộc với BTC / NCC, ≤ 200.
- Lỗi theo ô từ backend (`ApiError.fieldErrors`) gán vào đúng ô bằng `form.setFields`; lỗi chung hiện
  bằng `Alert` phía trên form. Chữ lỗi: `t("errors." + code)`, không có khóa thì `errors.Unknown`.
- Nút gửi khóa (`loading`) khi đang gọi API; không gửi trùng.

### Song ngữ

Thêm khóa vào `vi.json` / `en.json` (lấy chữ từ bản mẫu): `auth.*` (từng trang), `role.*` (5 vai trò +
mô tả), `validation.*`, `errors.*` cho **mọi** mã lỗi backend (`Validation`, `EmailTaken`,
`TokenInvalid`, `InvalidCredentials`, `AccountUnverified`, `AccountPending`, `AccountLocked`,
`SessionExpired`, `Unauthorized`, `Forbidden`, `TooManyRequests`) + `Network`, `Unknown`.

### Bảo mật phải giữ

- Access token chỉ trong bộ nhớ (biến của `authSession`), **không** `localStorage` / `sessionStorage`.
- Không tự đọc / ghi cookie refresh (HttpOnly — trình duyệt tự gửi).
- `returnUrl` chỉ nhận đường dẫn nội bộ. Không log token.
