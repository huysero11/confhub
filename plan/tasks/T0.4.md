## 1. Mục tiêu

Sau task này backend **có CSDL** (kết nối SQL Server qua EF Core, có migration đầu tiên) và có
**đường ống sự kiện**: một thay đổi dữ liệu và sự kiện đi kèm được lưu **trong cùng một transaction**
(Transactional Outbox), sau đó sự kiện được gửi qua RabbitMQ tới consumer (có Inbox chống xử lý trùng,
có thử lại khi lỗi). Chưa có sự kiện nghiệp vụ nào — test chứng minh đường ống chạy đúng.

**Vì sao cần Outbox?** Nếu lưu dữ liệu xong rồi mới gửi sự kiện, máy sập giữa hai bước thì mất sự kiện
(vd đã duyệt đăng ký nhưng không bao giờ gửi mail). Outbox ghi sự kiện vào bảng `OutboxMessage` cùng
transaction với dữ liệu → hoặc cả hai cùng thành công, hoặc cả hai cùng không; một tiến trình nền
đọc bảng đó và gửi đi sau.

## 3. Thiết kế

### Hạ tầng mới (docker-compose)

```yaml
  rabbitmq:
    image: rabbitmq:4-management
    container_name: confhub-rabbitmq
    ports:
      - "5672:5672"     # cổng API gửi/nhận tin nhắn (AMQP)
      - "15672:15672"   # trang quản lý http://localhost:15672 (guest/guest, chỉ máy dev)
```

### Gói (ghim phiên bản)

| Project        | Gói                                     | Phiên bản |
|----------------|-----------------------------------------|-----------|
| Infrastructure | Microsoft.EntityFrameworkCore.SqlServer | 10.0.12   |
| Infrastructure | MassTransit                             | 8.5.10    |
| Infrastructure | MassTransit.RabbitMQ                    | 8.5.10    |
| Infrastructure | MassTransit.EntityFrameworkCore         | 8.5.10    |
| Api            | Microsoft.EntityFrameworkCore.Design    | 10.0.12   |
| Tool (local)   | dotnet-ef                               | 10.0.12   |

`Microsoft.EntityFrameworkCore.Design` chỉ dùng cho lệnh tạo migration; `dotnet-ef` ghim trong
`.config/dotnet-tools.json` để mọi máy dùng cùng phiên bản (`dotnet tool restore`).
MassTransit **ghim 8.x** (8.5.10, Apache-2.0); bản 9 có giấy phép thương mại (PROJECT.md mục 8).

### Infrastructure

- `Persistence/ConfHubDbContext`: chưa có `DbSet` nghiệp vụ; `OnModelCreating` thêm 3 entity của
  MassTransit (`AddInboxStateEntity`, `AddOutboxMessageEntity`, `AddOutboxStateEntity`).
- `DependencyInjection.AddInfrastructure(services, configuration)`:
  - `AddDbContext<ConfHubDbContext>` với chuỗi kết nối `ConnectionStrings:ConfHub`.
  - `AddMassTransit`:
    - Outbox phía gửi: `AddEntityFrameworkOutbox<ConfHubDbContext>` + `UseSqlServer()` + `UseBusOutbox()`.
    - Inbox phía nhận: mọi endpoint dùng `UseEntityFrameworkOutbox<ConfHubDbContext>` → tin nhắn trùng
      không xử lý hai lần (consumer idempotent).
    - Thử lại khi consumer lỗi: `UseMessageRetry` với khoảng 1s, 5s, 15s.
    - Tự đăng ký mọi consumer trong project Infrastructure (hiện chưa có consumer nào trong `src`).
    - Transport RabbitMQ, đọc `RabbitMq:Host`, `RabbitMq:Username`, `RabbitMq:Password`.
- `Persistence/Migrations/`: migration `T0_4_MassTransitOutbox` (sinh bằng `dotnet ef`).

### Api

- `appsettings.Development.json`: `ConnectionStrings:ConfHub` =
  `Server=127.0.0.1,1433;Database=ConfHub;Trusted_Connection=True;TrustServerCertificate=True`;
  `RabbitMq`: `localhost` / `guest` / `guest` (không phải bí mật: chỉ tồn tại trên máy dev).
- `appsettings.json`: giữ khóa rỗng, không có giá trị thật.
- `Program.cs`: thêm `builder.Services.AddInfrastructure(builder.Configuration);`.
- `/health`: MassTransit tự thêm kiểm tra kết nối RabbitMQ → RabbitMQ tắt thì `/health` báo Unhealthy.

### Tạo CSDL

Không tự migrate khi khởi động API. Tạo/cập nhật bằng lệnh (đứng trong `be\`):
```cmd
dotnet ef database update --project src\ConfHub.Infrastructure --startup-project src\ConfHub.Api
```

### Luồng (sau task này)

```
Handler (từ T1.1): sửa dữ liệu + publish sự kiện
   → SaveChanges: dữ liệu + dòng OutboxMessage ghi trong CÙNG transaction
   → tiến trình nền (bus outbox) đọc OutboxMessage → gửi lên RabbitMQ → xóa dòng đã gửi
   → RabbitMQ → consumer: kiểm InboxState (đã xử lý chưa?) → xử lý → lỗi thì thử lại 1s/5s/15s
```

## 7. Kiểm thử thủ công cho Huy

1. `docker compose up -d` (gốc repo) → `docker ps` thấy `confhub-seq` và `confhub-rabbitmq`.
2. Mở `http://localhost:15672`, đăng nhập `guest`/`guest` → trang quản lý RabbitMQ.
3. Trong `be\`: `dotnet tool restore` rồi lệnh `dotnet ef database update ...` ở mục 3 →
   mở SSMS, refresh Databases: có `ConfHub` với 3 bảng + `__EFMigrationsHistory`.
4. Chạy API → RabbitMQ tab **Connections** thấy 1 kết nối từ ConfHub; `/health` trả `Healthy`.
5. `docker compose stop rabbitmq` → `/health` trả `Unhealthy` → `docker compose start rabbitmq`
   → lát sau `Healthy` trở lại (MassTransit tự kết nối lại).
