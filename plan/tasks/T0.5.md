## 1. Mục tiêu
Sau task này backend có đủ "đường ống" dùng chung cho mọi use case về sau: request đi qua MediatR, dữ liệu sai bị chặn ở `ValidationBehavior`, mọi lỗi trả về dạng **ProblemDetails** thống nhất, log có cấu trúc đổ về **Seq** (chạy bằng Docker Compose), và có trang tài liệu API (OpenAPI + Scalar). Chưa có bảng nào trong CSDL.

## 2. Phạm vi
**Làm:**
- `docker-compose.yml` ở gốc repo, chỉ có service `seq`.
- Domain: `BaseEntity`, `IAggregateRoot`, `IDomainEvent`, `DomainException`.
- Application: MediatR 12.x + FluentValidation, `ValidationBehavior`, exception nghiệp vụ `NotFoundException`, `ConflictException`, `ForbiddenException`, extension `AddApplication()`.
- Api: `ExceptionHandlingMiddleware` (tự viết, `try/catch`) ánh xạ exception → ProblemDetails; Serilog (Console + Seq) + request logging; OpenAPI + Scalar (chỉ Development); `Program.cs` gọi `AddApplication()`.
- Test: project mới `tests/ConfHub.Application.Tests` + test bổ sung trong `ConfHub.Api.IntegrationTests`.

**Không làm (để task khác):**
- EF Core, DbContext, chuỗi kết nối SQL Server, migration → **T0.4** (Outbox của MassTransit là thứ đầu tiên cần DbContext).
- `IRepository`/`IReadRepository` + Specification, SaveChangesInterceptor (audit), sinh Guid tuần tự → **T1.1** (aggregate đầu tiên).
- Phân trang, Mapster → task danh sách đầu tiên (G3).
- `ICurrentUser`, `[MustHavePermission]`, JWT → T1.1.
- `TimeRange` → task đầu tiên dùng (G2/G3).
- `AddInfrastructure()` → chưa có gì để đăng ký, T0.4 mới tạo.

## 3. Thiết kế
- **CSDL:** không.
- **Hạ tầng mới:** container `seq` trong `docker-compose.yml`:
  ```yaml
  services:
    seq:
      image: datalust/seq
      container_name: confhub-seq
      restart: unless-stopped
      environment:
        ACCEPT_EULA: "Y"
        SEQ_FIRSTRUN_NOAUTHENTICATION: "true"
      ports:
        - "5341:80"
      volumes:
        - seq-data:/data
  volumes:
    seq-data:
  ```
  Giao diện + nhận log cùng ở `http://localhost:5341`.

- **Gói (ghim major, lấy bản vá mới nhất):**
  | Project | Gói |
  |---|---|
  | Application | `MediatR` **12.x (không lên 13 — giấy phép thương mại)**, `FluentValidation` + `FluentValidation.DependencyInjectionExtensions` |
  | Api | `Serilog.AspNetCore`, `Serilog.Sinks.Seq`, `Microsoft.AspNetCore.OpenApi` 10.x, `Scalar.AspNetCore` |
  | Application.Tests | xUnit (template `dotnet new xunit`), không thêm thư viện mock/assert nào khác |

- **Domain (`ConfHub.Domain/Common/`):**
  - `BaseEntity`: `Guid Id { get; protected set; }` + danh sách domain event private, `IReadOnlyCollection<IDomainEvent> DomainEvents`, `protected AddDomainEvent(...)`, `ClearDomainEvents()`. Không tự sinh Id (EF sinh ở T1.1).
  - `IAggregateRoot` (marker), `IDomainEvent` (marker, **không** phụ thuộc MediatR — Domain không tham chiếu gói nào).
  - `DomainException(string code, string message)`: vi phạm bất biến nghiệp vụ trong aggregate.

- **Application (`ConfHub.Application/Common/`):**
  - `Behaviors/ValidationBehavior<TRequest,TResponse>`: chạy mọi `IValidator<TRequest>`; có lỗi → ném `FluentValidation.ValidationException`; không có validator → đi tiếp.
  - `Exceptions/`: `NotFoundException(string entity, object key)`, `ConflictException(string code, string message)`, `ForbiddenException(string message)`.
  - `DependencyInjection.AddApplication(this IServiceCollection)`: đăng ký MediatR (quét assembly Application) + `ValidationBehavior` + validator (quét assembly).

- **Api:**
  - `ErrorHandling/ExceptionHandlingMiddleware` tự viết (`try { await next } catch`), đăng ký bằng `app.UseMiddleware<>()`; tự ghi JSON `application/problem+json` (tự điền `title`, `traceId`). Response đã bắt đầu gửi → ném lại; client tự ngắt kết nối → bỏ qua. (Chốt 2026-09-28: tự viết thay `IExceptionHandler` để hiểu rõ cơ chế middleware.) Ánh xạ:
    | Exception | HTTP | `code` (extension) |
    |---|---|---|
    | `ValidationException` (FluentValidation) | 400 | `Validation` + `errors`: `{ tênTrường: [mã lỗi] }` |
    | `NotFoundException` | 404 | `NotFound` |
    | `ConflictException` | 409 | mã truyền vào |
    | `DomainException` | 422 | mã truyền vào |
    | `ForbiddenException` | 403 | `Forbidden` |
    | Khác | 500 | `Internal` — **không** lộ message/stack ngoài Development |
    Mọi response có `traceId`. BE trả **mã lỗi**, FE dịch bằng i18n (không dịch ở BE).
  - Serilog: cấu hình đọc từ `appsettings.json` (mức log, sink Console + Seq `http://localhost:5341`), `UseSerilogRequestLogging()`. Không dùng bootstrap logger tĩnh gây lỗi "logger is already frozen" khi test tạo nhiều `WebApplicationFactory`.
  - OpenAPI: `AddOpenApi()`; chỉ Development: `MapOpenApi()` + `MapScalarApiReference()` (trang `/scalar/v1`).
  - `Program.cs` giữ gọn, đọc theo thứ tự: log → service → pipeline → endpoint.

- **Luồng một request (sau task này):**
  `HTTP → Serilog request logging → ExceptionHandlingMiddleware → Authorization → Controller → MediatR → ValidationBehavior → Handler → (lỗi ở đâu cũng về ApiExceptionHandler → ProblemDetails)`

Điểm chính:
- **#20** thêm gói (đứng trong `be\`): `Microsoft.AspNetCore.OpenApi` 10.0.12,
  `Scalar.AspNetCore` 2.17.10, `Serilog.AspNetCore` 10.0.0, `Serilog.Sinks.Seq` 9.1.0
  (`dotnet add src\ConfHub.Api package <tên> --version <số>`).
- **appsettings.json**: `MinimumLevel` (mức log), `WriteTo` gửi log ra Console và Seq
  `http://localhost:5341`.
- **ExceptionHandlingMiddleware**: `InvokeAsync` = `try { await next(context); } catch { ... }`.
  - `next` là "phần phía sau" (controller, MediatR, handler); lỗi ở đâu cũng bay ngược về `catch`.
  - `catch (OperationCanceledException) when (...)`: client tự ngắt → bỏ qua, không phải lỗi.
  - `Response.HasStarted`: đã gửi dở response thì không sửa được nữa → `throw;` ném lại.
  - `MapExceptionToProblem`: chuỗi `if (exception is ...)` chọn status + `code` theo loại lỗi;
    lỗi 500 ẩn message ngoài dev và là lỗi duy nhất ghi `LogError`.
  - `BuildProblem` dựng lỗi thường; `BuildValidationProblem` dựng lỗi 400, gom mã lỗi theo
    từng trường bằng `foreach`.
  - `WriteProblemAsync`: tự điền `title`, `traceId` rồi `WriteAsJsonAsync` với
    content type `application/problem+json`.
- **Program.cs**: 4 khối log → service → pipeline → endpoint; thứ tự các dòng `app.Use...`
  chính là thứ tự request đi qua.

⏸ `dotnet build` pass → chạy API, mở `/health`, `/scalar/v1`, xem log trong Seq.
