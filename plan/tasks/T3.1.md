- **Nhóm:** G3

## 1. Mục tiêu

Sau task này Ban tổ chức (tài khoản mẫu `organizer@confhub.local`) dùng API để **tạo hội nghị** bằng khoảng ngày +
giờ mặc định, sửa thông tin, **chỉnh từng ngày và khung nghỉ**, **khai phòng** và **track**; chỉ thấy và sửa được
hội nghị của chính mình. Thử toàn bộ qua Scalar; giao diện làm ở T3.3.

Task cũng dựng những thứ các task G3–G5 dùng lại:
- Danh mục quyền nghiệp vụ đầu tiên (`Permissions`) và seed quyền cho vai trò `Organizer`.
- Value object `TimeRange` (khoảng giờ trong ngày, bước 15 phút, kiểm chồng / chứa) — lõi của H1, H3, H5.
- Kiểm "là chủ hội nghị" (BR16) và giờ nơi tổ chức (`VenueClock`).

## 3. Thiết kế

### Luồng tổng

```
Request BTC (Bearer JWT)
  → [MustHavePermission(Conference.Manage | Room.Manage | Session.Manage)] (cơ chế T1.4)
  → Manage*Controller → Command / Query (MediatR) → ValidationBehavior (FluentValidation: định dạng, độ dài, bước 15')
  → Handler: đọc Conference qua repository → ConferenceAccess.EnsureOwned (OwnerId ≠ người gọi → 404)
      → gọi phương thức nghiệp vụ của aggregate (Conference / Room / Track) — bất biến sai → DomainException → 422
      → repository.SaveChangesAsync / Add / Update / Delete
  → Controller trả 201 { id } / 200 DTO / 204
```

Ví dụ tạo hội nghị: `POST /api/manage/conferences` { 03–04/12/2026, 08:00–17:00, hạn 01/12 23:59 } →
`Conference.Create` tạo 2 `ConferenceDay` 08:00–17:00 → lưu 1 lần → `201 { id }`.

### Hạ tầng mới đăng ký ở task này

- Không thêm gói, không thêm container.
- Cấu hình mới `Venue:TimeZoneId` = `Asia/Ho_Chi_Minh` (`appsettings.json`). Options `VenueOptions`
  (Options pattern + `ValidateOnStart`: id rỗng hoặc không tìm được múi giờ → API dừng khi khởi động).
- DI (Infrastructure, `Venue/VenueServiceRegistration.AddVenue`): `VenueOptions` + singleton `VenueClock` dựng từ
  `TimeProvider` và `TimeZoneInfo.FindSystemTimeZoneById(TimeZoneId)`.
- Api: `AddControllers().AddJsonOptions(...)` thêm `TimeOnlyHourMinuteJsonConverter` (đọc / ghi `"HH:mm"`).

### CSDL — migration `T3_1_Conferences`

| Bảng             | Cột (ngoài `Id`, `CreatedAt`)                           |
|------------------|---------------------------------------------------------|
| `Conferences`    | xem danh sách dưới                                      |
| `ConferenceDays` | `ConferenceId`, `Date`, `StartTime`, `EndTime`          |
| `BreakSlots`     | `ConferenceDayId`, `Name` (100), `StartTime`, `EndTime` |
| `Rooms`          | `ConferenceId`, `Name` (50), `Capacity`                 |
| `Tracks`         | `ConferenceId`, `NameVi` (100), `NameEn` (100, null)    |

- Unique: `ConferenceDays` (`ConferenceId`, `Date`), `Rooms` (`ConferenceId`, `Name`), `Tracks` (`ConferenceId`,
  `NameVi`).
- `Conferences`: `NameVi` (200), `NameEn` (200, null), `DescriptionVi` (4000, null), `DescriptionEn` (4000, null),
  `Venue` (300), `RegistrationCloseAt` (`datetime2`), `RequireApproval` (`bit`), `Status` (chuỗi 30), `OwnerId`
  (FK → `Users`, **Restrict**, có index).
- Kiểu cột: `Date` là `date`; `StartTime` / `EndTime` là `time(0)`.
- Mọi FK tới `Conferences` / `ConferenceDays` là **Cascade** (xóa hội nghị kéo theo ngày, khung nghỉ, phòng, track).
- `RegistrationCloseAt`: `datetime2`, lưu UTC; cấu hình EF đọc lên gán `DateTimeKind.Utc` (JSON trả có `Z`).
- `StartTime` / `EndTime` là 2 cột của value object `TimeRange` (complex property EF Core, xem Domain).
- Tên phòng, tên track không phân biệt hoa thường nhờ collation mặc định của SQL Server (`..._CI_AS`) — unique index
  chặn cả `P101` / `p101`.
- **Seed:** `RoleConfiguration.HasData` gán `Organizer` = `["Conference.Manage", "Room.Manage", "Session.Manage"]`
  → migration có `UpdateData` cho dòng Roles đó. Các vai trò khác vẫn `[]`.

### Domain (`ConfHub.Domain/`)

**`Common/TimeRange`** — value object khoảng giờ trong một ngày (`sealed record`):
- `TimeRange.Create(TimeOnly start, TimeOnly end)`: start < end, cả hai là bội số 15 phút (giây = 0) — sai →
  `DomainException(InvalidTimeRange)` (lưới an toàn; dữ liệu từ API đã qua validator).
- `StepMinutes = 15`, `Start`, `End`, `DurationMinutes`, `Overlaps(other)` (giao nhau thật sự: chạm đầu mút
  **không** tính, PROJECT.md 6.6 ý 2), `Contains(other)` (nằm trọn, tính cả đầu mút), `IsQuarterHour(TimeOnly)`
  (static, validator dùng lại).
- Constructor private không tham số cho EF.

**`Accounts/Permissions`** — hằng số mã quyền: `ConferenceManage = "Conference.Manage"`, `RoomManage`,
`SessionManage`; comment ghi "mỗi nhóm thêm quyền của mình" (T3.2 thêm `SpeakerManage`).

**`Conferences/`**:

| File                   | Nội dung                                                    |
|------------------------|-------------------------------------------------------------|
| `ConferenceStatus`     | enum 5 trạng thái của spec mục 2 (G3 chỉ dùng `Draft`)      |
| `ConferenceDetails`    | `record` gom thông tin sửa được (danh sách dưới)            |
| `Conference`           | Aggregate root: thông tin + `Days` (mỗi ngày có `Breaks`)   |
| `ConferenceDay`        | Entity con: `ConferenceId`, `Date`, `Hours` (`TimeRange`)   |
| `BreakSlot`            | Entity con: `ConferenceDayId`, `Name`, `Time` (`TimeRange`) |
| `Room`                 | Aggregate root: `ConferenceId`, `Name`, `Capacity`          |
| `Track`                | Aggregate root: `ConferenceId`, `NameVi`, `NameEn`          |
| `ConferenceErrorCodes` | Mã lỗi nhóm G3 (bảng dưới)                                  |

- `ConferenceDetails(NameVi, NameEn, DescriptionVi, DescriptionEn, Venue, RegistrationCloseAt (UTC),
  RequireApproval)` — tránh phương thức 8 tham số; dùng cho `Create` và `UpdateDetails`.
- `Track.MaxPerConference = 5`.

`Conference` — mọi thay đổi ngày / khung nghỉ đi qua aggregate (giữ bất biến cả hội nghị):
- `Create(ownerId, details, startDate, endDate, defaultHours, today, nowUtc, venueTimeZone)`: tạo `Draft`, một
  `ConferenceDay` cho mỗi ngày từ `startDate` tới `endDate`. Kiểm: số ngày ≤ 14 (`TooManyDays`), `startDate ≥ today`
  (`DayInPast`), hạn đăng ký > `nowUtc` (`RegistrationCloseInPast`), hạn ≤ giờ bắt đầu ngày đầu
  (`RegistrationCloseAfterStart`).
- `UpdateDetails(details, nowUtc, venueTimeZone)`: hạn đăng ký **đổi** thì phải > `nowUtc`; luôn ≤ giờ bắt đầu ngày đầu.
- `AddDay(date, hours, today, venueTimeZone)` → trả `ConferenceDay`: chưa có ngày đó (`DayDateTaken`), ≤ 14 ngày,
  `date ≥ today`, hạn đăng ký vẫn ≤ giờ bắt đầu ngày đầu.
- `UpdateDay(dayId, date, hours, today, venueTimeZone)`: đổi ngày thì ngày mới chưa có và ≥ `today`; mọi khung nghỉ
  vẫn nằm trong giờ mới (`BreakOutsideDay`); hạn đăng ký ≤ giờ bắt đầu ngày đầu.
- `RemoveDay(dayId)`: còn ít nhất 1 ngày khác (`LastDayRequired`).
- `AddBreak(dayId, name, time)` → trả `BreakSlot`, `UpdateBreak(dayId, breakId, name, time)`,
  `RemoveBreak(dayId, breakId)`: khung nghỉ nằm trọn trong giờ ngày (`BreakOutsideDay`), không chồng khung khác cùng
  ngày (`BreakOverlap`; khi sửa thì bỏ qua chính nó).
- `FindDay(dayId)` / `ConferenceDay.FindBreak(breakId)` trả `null` nếu không có — handler đổi thành 404. Phương thức
  nghiệp vụ nhận id không tồn tại → `InvalidOperationException` (lỗi lập trình, handler đã kiểm trước).
- `IsOwnedBy(userId)`.
- Giờ bắt đầu ngày đầu (UTC) = `TimeZoneInfo.ConvertTimeToUtc(ngày sớm nhất + giờ bắt đầu, venueTimeZone)`; viết
  1 hàm private dùng chung cho các kiểm tra hạn đăng ký.
- Chuỗi: cắt khoảng trắng; `NameEn`, `DescriptionVi`, `DescriptionEn` rỗng → `null` (như `User.TrimOrNull`).
- `ConferenceDay`, `BreakSlot`: constructor / phương thức sửa là `internal` — chỉ `Conference` gọi được.

`Room.Create(conferenceId, name, capacity)`, `room.Update(name, capacity)`; `Track.Create(conferenceId, nameVi,
nameEn)`, `track.Rename(nameVi, nameEn)` — cắt khoảng trắng, `NameEn` rỗng → `null`. Không kiểm trùng (handler +
unique index làm), không kiểm số track (handler đếm).

| `DayDateTaken`                | 422  | `Conference`                |
| `TooManyDays`                 | 422  | `Conference` (và validator) |
| `DayInPast`                   | 422  | `Conference`                |
| `LastDayRequired`             | 422  | `Conference`                |
| `RegistrationCloseAfterStart` | 422  | `Conference`                |
| `RegistrationCloseInPast`     | 422  | `Conference`                |
| `BreakOutsideDay`             | 422  | `Conference`                |
| `BreakOverlap`                | 422  | `Conference`                |

`…` = `/api/manage/conferences`. Kiểu trả: tạo → `CreatedIdResponse`; danh sách → `List<…Response>`; chi tiết hội nghị
→ `ConferenceDetailResponse`. Tham số command / query (id lấy từ route, phần còn lại từ body):
- `CreateConferenceCommand(NameVi, NameEn, DescriptionVi, DescriptionEn, Venue, StartDate, EndDate, DayStartTime,
  DayEndTime, RegistrationCloseAt, RequireApproval)`.
- `UpdateConferenceCommand(ConferenceId, NameVi, NameEn, DescriptionVi, DescriptionEn, Venue, RegistrationCloseAt,
  RequireApproval)` — không đổi khoảng ngày (sửa ở từng ngày).
- Ngày: `(ConferenceId, [DayId,] Date, StartTime, EndTime)`; khung nghỉ: `(ConferenceId, DayId, [BreakId,] Name,
  StartTime, EndTime)`; phòng: `(ConferenceId, [RoomId,] Name, Capacity)`; track: `(ConferenceId, [TrackId,]
  NameVi, NameEn)`; xóa / đọc: chỉ các id.
- Thư mục: 11 use case đầu trong `Conferences/`, phòng trong `Rooms/`, track trong `Tracks/` (cùng cấp `Accounts/`).
- `RegistrationCloseAt` trong command là `DateTimeOffset` (client gửi kèm múi giờ) → handler đổi `.UtcDateTime`.
- Mọi handler: lấy `currentUser.UserId`, đọc hội nghị, `ConferenceAccess.EnsureOwned` **trước** mọi việc khác.
  Phòng / track không thuộc hội nghị trong route → 404 (kiểm `room.ConferenceId == conferenceId`).
- Kiểm trùng tên phòng / track: tìm theo spec, có bản ghi **khác** chính nó → `ConflictException(RoomNameTaken)`.
  Hai request cùng lúc vượt kiểm tra → unique index chặn → `EfRepository` đã đổi thành 409 `Duplicate` (chấp nhận).
- `CreateTrack`: đếm track của hội nghị ≥ 5 → `DomainException(TooManyTracks)`.
- Xóa hội nghị: `DeleteAsync(conference)` — CSDL cascade phòng, track.

**Response** (`Conferences/`, `Rooms/`, `Tracks/` — map tay bằng hàm tĩnh `From…` hoặc `Query.Select`):
- `ConferenceListItemResponse(Id, NameVi, NameEn, Venue, Status, FirstDate, LastDate, RoomCount)` — `Status` là
  chuỗi (`ToString()`), `FirstDate` / `LastDate` = ngày sớm / muộn nhất (tính trong `Select`).
- `ConferenceDetailResponse(Id, NameVi, NameEn, DescriptionVi, DescriptionEn, Venue, RegistrationCloseAt,
  RequireApproval, Status, Days)` + `FromConference(conference)`; `ConferenceDayResponse(Id, Date, StartTime,
  EndTime, Breaks)`; `BreakSlotResponse(Id, Name, StartTime, EndTime)` — ngày sắp theo ngày, khung nghỉ theo giờ.
- `RoomResponse(Id, Name, Capacity)`, `TrackResponse(Id, NameVi, NameEn)`.

**Validator** (lỗi → 400 `Validation`, mã từng trường):

| Command                   | Quy tắc                                               |
|---------------------------|-------------------------------------------------------|
| Create / UpdateConference | Tên, mô tả, địa điểm, hạn đăng ký (danh sách dưới)    |
| CreateConference (thêm)   | Khoảng ngày + giờ mặc định (danh sách dưới)           |
| Add / UpdateConferenceDay | `Date` bắt buộc; giờ như giờ mặc định                 |
| Add / UpdateBreakSlot     | `Name` bắt buộc ≤ 100; bước 15'; kết thúc sau bắt đầu |
| Create / UpdateRoom       | `Name` bắt buộc ≤ 50; `Capacity` 1–10 000             |
| Create / UpdateTrack      | `NameVi` bắt buộc ≤ 100; `NameEn` ≤ 100               |

- Hội nghị: `NameVi` bắt buộc ≤ 200 (tính sau khi cắt trắng); `NameEn` ≤ 200; mô tả ≤ 4000; `Venue` bắt buộc ≤ 300;
  `RegistrationCloseAt` bắt buộc.
- Khoảng ngày: `StartDate ≤ EndDate`; số ngày ≤ 14 (`TooManyDays`). Giờ (mặc định hoặc của một ngày): bước 15'
  (`QuarterHourStep`), kết thúc sau bắt đầu (`EndNotAfterStart`), dài ≥ 60' (`DayTooShort`).
- Validator **không** dùng đồng hồ: "ở quá khứ" là bất biến của aggregate (nhận `today` / `nowUtc` từ `VenueClock`).
